# Native testing in mncs-math

Math verifies in two complementary layers. Neither replaces the other.

## Layer 1 — frozen execution corpora (all modules)

`tests/corpora/*-corpus.json` (+ `*-traps-corpus.json`) generated by
`tools/mkcorpus.py` from authored oracle tables in `tests/tables/`.
They pin exact values — including exact f64 bit patterns — on all five
executable backends, and trap corpora pin deterministic
`runtime_failure`. This layer is the only place that can express an
**expected trap**: native tests have no trap-expectation assertion (see
"Known test-system gap" below), so every trapping behavior must keep a
trap-corpus case.

## Layer 2 — native `mncs-test` suites (scalar, float)

`tests/native/*.mncs` (profile 0.18) hold `test` declarations run by the
compiler-owned `mncs test` command. They pin LAWS, not values:

- identity (`x + 0 = x`), commutativity (exact integer/float add/mul),
  inverses (add/sub, mul/div through checked wrappers);
- boundary reasons (`checked_add(MAX,1)` → `reason_overflow`,
  `checked_div(7,0)` → `reason_div_by_zero`, `abs_checked(MIN)` → Err);
- float discipline: exact `feq` pins, order-dependence as INequality
  (`fsum_left != fsum_right` on the discriminating vector), benign
  agreement, and the `0.1 + 0.2 != 0.3` witness paired with its
  `approx_eq` acceptance;
- determinism (replay equality) and bounded generative sweeps with
  fixed seeds (`mncs.test.generative.replay(seed, index, bound)`).

Run them (toolchain binary + three library roots):

```bash
export MNCS_LIBRARY_PATH="<mncs-test>/native:$PWD/src:<mncs-language>/library"
<mncs> test tests/native/scalar_properties.mncs --format text
<mncs> test tests/native/float_properties.mncs --format text
```

`--format json` emits the result contract (per-test identity
`mncs:0.2:test-case:<module>::<name>::<hash>`, expected/actual,
assertion code, backend, artifact identity) consumed by Debug and
retained as verification evidence.

## Ownership rules

- Approximate equality is math-owned: `mncs.math.approx.v1`
  (`approx_abs`/`approx_rel`/`approx_eq`, total over finite inputs,
  trapping on non-finite per the float trap rule). Do not add float
  tolerance assertions to `mncs-test`; that policy is domain-specific.
- Generic assertions (`equals_i64/bool/bytes`, suite aggregation,
  generative streams, snapshots) are test-owned: import from
  `mncs.test.*`, never reimplement.
- Cross-profile imports are normal: 0.18 test modules `use` 0.6–0.12
  library modules; each module keeps its lowest parsing profile.

## Adding coverage

- New behavior in an existing module: extend its oracle table
  (hand-derived or Python-oracle cross-checked values, never tool
  output copied blind) + regenerate with `tools/mkcorpus.py <module>`,
  and add the LAW to the matching native suite where one exists.
- New module: `src/math/<name>.mncs` + `tests/tables/<name>.json`
  (+ `-traps` table if it traps) + corpus + 5-backend gate via
  `scripts/check.sh <name>` then `scripts/conformance.sh`.
- Failing native test → Debug: `mncs-debug import-test <result.json>`
  produces a witness (program/request/IR/SSA/trace artifacts); the
  failure record already names entry, assertion code, expected/actual,
  backend, and artifact identity.

## Tooling note: Doctor's profile registry lags 0.18

`mncs-doctor doctor` reports `[DOC102|error] unknown profile 0.18` on
`tests/native/*.mncs`. The headers are correct: the current toolchain
elaborates and runs 0.18 `test` declarations (31/31 PASS here), and
`mncs-test`'s own self-suite declares `mncs 0.18`. Doctor's known-profile
registry has not caught up with the toolchain — a Doctor-side gap, not a
math defect. Do not "fix" it by lowering the test headers: older profiles
cannot declare `test`s.

## Known test-system gap

Native tests cannot assert an expected trap (a trapping body reports a
runtime failure, never a pass). Until `mncs-test` gains structured
failure expectations, trap coverage stays exclusively in
`*-traps-corpus.json`. Recorded as a test-system pressure (non-blocking).
